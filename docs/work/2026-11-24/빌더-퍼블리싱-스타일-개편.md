# 빌더 퍼블리싱 스타일 개편 작업 기록

- 작성일: 2026-11-24 (한국시간, Asia/Seoul)
- 기준: 최신 [설계 문서](../../history/2026-11-24/빌더-퍼블리싱-스타일-개편.md)를 다시 읽고 구현했다.
- 적용 범위: `/admin/builder/react-flow/scenario-flow`의 스타일과 기존 편집 UI 정리.

## 주요 변경사항

- 설계의 기본 범위를 적용했다. 라이트·다크 이미지의 녹색 강조색을 선택하고 기존 전역 theme를 읽는다. 추가 테마 저장 호출은 없다.
- 페이지 전용 CSS 변수와 `BuilderAppearanceContext`로 헤더·팔레트·캔버스·미니맵·카드·속성 패널을 테마에 맞췄다. 공유 화면의 기본 외형과 내부 모달의 context 경계를 유지했다.
- 노드의 얇은 타입별 경계·작은 아이콘·선택 ring·제목 말줄임·우측 Edit, 그룹 직접 자식 수 배지·원형 추가 버튼을 적용했다. 사용자 노드 색과 기존 그룹 폭·배치 상수, 핸들 ID는 유지했다.
- 더보기를 기존 명령을 유지한 텍스트 목록으로 정리하고 기존 권한 검사가 있는 Edit 경로를 연결했다. API 테스트와 Ungroup도 보존했다.
- 속성 패널에 타입 헤더·닫기·BASIC/BEHAVIOUR 구획·고정 저장 영역을 적용하고 작은 화면의 패널 표시를 보완했다. 모니터 버튼의 활성 표시는 실제 로그 표시 상태를 따르도록 수정했다.
- `scenario-tab-menu`의 JSX·트리거·기존 메뉴 스타일·타입/버전 helper·탭 전환/캐시를 보존했다. 기존 정의 저장·버전 생성·그룹 내부 연결 표시와 실행 규칙은 유지했다.

## 변경 파일

소스 경로의 기준은 `app/(siderbar-header)/admin/builder`다.

- 신규: `components/BuilderAppearance.tsx`, `components/BuilderAppearance.module.css`.
- 페이지: `react-flow/scenario-flow/page.tsx`, `ScenarioFlow.module.css`.
- 라이브러리·속성 패널: `components/NodesTreeUI.tsx`, `NodeController.tsx`, `NodeController.module.css`.
- 노드: `components/nodes/NodeWrapper.jsx`, `GroupNode.jsx`, `ApiNode.jsx`, `ScenarioNode.tsx`, `DelayNode.jsx`, `YnBranchNode.tsx`, `ChatNodes.module.css`.
- 속성 내용·모달 경계: `components/controllers/FormNodeController.tsx`, `ScenarioNodeController.tsx`, `common/ChainNextCheckbox.jsx`.
- 연결선: `components/edges/CustomOrthogonalEdge.jsx`.
- 문서: `README.md`, `AGENTS.md`, `CLAUDE.md`, `docs/pages/sidebar-header/admin/builder.md`, `HISTORY.md`, `WORK_HISTORY.md`, 본 작업 기록. 기존 설계 문서와 사용자 자료는 보존했다.

## DB 변경 여부

없음. 스키마·마이그레이션·저장 API·실행 엔진·Firebase/FastAPI 서비스는 변경하지 않았다. 검증에서도 실제 DB·외부 API에 연결하지 않았다.

## 검증 결과

- `pnpm lint`: 통과. 샌드박스의 node_modules 읽기 EPERM으로 최초 실행이 실패해 같은 명령을 샌드박스 밖에서 실행했다.
- `pnpm exec tsc --noEmit --incremental false --pretty false`: 변경 전부터 존재한 `scenarioTabs.ts:7`의 `ScenarioType(agent)`/`ScenarioTabKind(unit)` 불일치로 실패. 변경 후 검사에서도 같은 오류만 보고되었다.
- `pnpm build`: Next.js 프로덕션 컴파일 성공. 이후 같은 기존 타입 오류에서 중단되어 전체 빌드 성공은 아니다.
- `node --test scripts/emulator-api-routing.test.mjs scripts/delay-duration.test.mjs core/scenario-core/group-api-routing.test.mjs`: 20개 통과. API 성공·Error·레거시 onFail·그룹 끝 복귀와 Delay 변환/검증 회귀 확인.
- 임시 Edge 컴포넌트 하네스: 라이트·다크 각각 13개 검사 통과. 실제 변경한 React 컴포넌트·MUI와 CSS를 사용하고 store·React Flow 위치 훅·인증/서비스 경계만 로컬 대체했다. 핸들 ID 보존, read-only 미리보기, 자식 수, 테마 전환 시 데이터 무변경, 비활성 presentation의 기존 외형, 메뉴 명령·Edit callback, 패널 닫기·미저장, 속성 변경·기존 update 호출을 확인했다. 두 테마 스크린샷도 확인했다. 하네스·브라우저 프로필은 저장소 밖 임시 폴더에만 생성했다.
- 전체 로그인 화면·실제 React Flow의 드래그/연결·실시간 저장·다른 시나리오 탭 전환은 위 분리 검증에 포함되지 않는다.
- 최종 diff·메뉴 보존·문서 상대 링크 검증 결과는 최종 확인 후 아래에 기록한다.

## 미완료·후속 확인

- 기존 `scenarioTabs.ts` 타입 불일치는 메뉴 관련 파일을 이번 스타일 작업에서 제외한 설계에 따라 수정하지 않았다. 전체 빌드를 통과시키려면 Agent/Unit 분류 기준을 별도로 정리해야 한다.
- 설계의 유보 사항인 좌우 +/새 Node Picker, Branch 합류 기준 편입 제한, 전체 펼침·접기 명령, 빈 제목 오류 정책, 시나리오 전체 dirty·이탈 확인, 실제 배포와 Published 표시, 삭제 확인·Undo 토스트는 추가하지 않았다.
- 실제 관리자 세션에서 화면 크기별 비교, 모든 노드·폼 미리보기, 드래그/정렬/그룹화·edge 경로, 내부 모달·Orkes·조회 화면과 Firebase/FastAPI 테스트 시나리오 저장을 후속 확인한다.
- 재개 시 위 설계와 본 기록을 다시 읽고, 기존 타입 오류의 처리 범위와 설계 결정표에서 추가로 채택할 기능을 확인한다.
